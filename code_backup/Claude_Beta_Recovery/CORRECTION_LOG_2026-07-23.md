# Correction: Table A.1 was built on the buggy AR(1) model

**Status: fixed.** Table A.1 (`tab:appendix_params` in `tex/july_16_2026.tex`)
and the two sentences summarizing its outcome have been updated. This log
records what was found, how it was traced, the new numbers, and what
changed in the paper.

## What was found

Table A.1's currently published numbers were generated via
`code_backup/Claude_Beta_Recovery/Appendix_A/reproduction_2026-07-20/psd_beta_recovery_per_draw_binned_fit.py`,
whose `DATA_DIR` points to an external path:
`/Users/home/Documents/science/project/johannes/publication/paper_one/data/Appendix_A_Inference_OutPut_red_noise_psd_recovery_beta_<B>_and_1000_time_step_and_7_unit_shift_v2.npz`.

Traced the provenance of those `.npz` files (dated 2025-03) to
`colored_noise_light_curve_generation_with_one_beta_and_multiple_time_lengths.py`
in that same external directory, which contains:

```python
from simple_HMC import model
from simple_HMC import run_inference_on_slice
```

`simple_HMC.py`'s `model()` function is the exact file already confirmed
buggy in this session (see `CORRECTION_LOG_2026-07-21.md`):

```python
y_prev = numpyro.sample("y_prev", dist.Normal(mean, 1))
```

-- a fixed unit-variance initialization instead of the correct AR(1)
stationary variance `sigma/sqrt(1-alpha**2)`. This is airtight: **the data
behind the currently published Table A.1 was generated by the buggy
model**, not `ar1_hmc_v2.py` (the corrected model used everywhere else in
this session's Appendix A work, including Fig. A.1 and Fig. A.2 as
regenerated 2026-07-23).

## What was regenerated

Same per-draw method as `psd_beta_recovery_per_draw_binned_fit.py`
(periodogram -> 9 log-frequency bins -> multi-start bounded `curve_fit`,
percentiles across all posterior draws), applied to the corrected model's
T=1000, shift=7 posteriors already used for Fig. A.1/A.2
(`plots/appendix_a/data/`):

- `plots/appendix_a/generate_table_A1.py` -- beta=3.0 and beta=4.0 rows
  (2000-draw short chain; ESS/r_hat for these two are already confirmed
  good in this session's earlier diagnostics work, no mixing concern).
- `plots/appendix_a/generate_table_A1_beta1.7_longchain.py` -- beta=1.7
  row, using the 20,000-sample long chain thinned by 50 (400
  near-independent draws) instead of the 2000-sample short chain. The
  short chain's beta=1.7 result is already known from earlier this
  session to have ESS~=41 for tau_param (severe autocorrelation, see
  `Appendix_A/reproduction_2026-07-20/BAYESIAN_DIAGNOSTICS_LEARNINGS.md`)
  -- using it directly risked baking that known mixing artifact into the
  new table. Cross-checked: the long-chain, properly-thinned result
  (p5=1.587, median=1.591, p95=1.595) came out essentially identical to
  the raw short chain's (p5=1.586, median=1.591, p95=1.595) -- so the
  tight interval is a genuine feature of the within-run posterior, not a
  mixing artifact, but the long-chain version was used regardless for
  defensibility (it is not dependent on the known-bad short chain).

## Old vs new numbers

| Row | Old (buggy model) | New (corrected model) | True value | Bracketed (old) | Bracketed (new) |
|---|---|---|---|---|---|
| beta_1 | 1.96 / 1.97 / 1.98 | 1.59 / 1.59 / 1.59 | 1.70 | No | No |

| beta_3 | 3.77 / 3.83 / 4.09 | 3.73 / 3.86 / 3.92 | 4.00 | Yes (barely) | No |

(columns: 5% / median / 95%; "bracketed" = does the [5%,95%] interval
contain the true value)

**This is not just a number update.** The old (buggy) table's narrative
claim -- "true beta falls within the credible interval for 2 of 3 cases
(beta=3,4), only beta=1.7 misses" -- is no longer true under the corrected
model. All three cases now miss. This required updating two sentences
that stated the old claim, not just the table:

- sec. 3.4.2 (`verification_results_psd`, main text) -- the sentence
  introducing the colorednoise validation result.
- Appendix A, the sentence immediately preceding Table A.1.

Both now state that the true value falls outside the [5%,95%] interval
for all three cases, with beta=1.7's miss attributed (as before) to
ordinary periodogram-estimator scatter, and beta=3/beta=4's miss now
attributed to the AR(1) model's structural slope-2 PSD ceiling --
consistent with, and cross-referencing, the "two distinct failure modes"
explanation already written into sec. `verification_results_psd` ("The
case for beta") from earlier this session's work. The 40-realization
footnote on beta=1.7 (median=1.60, mean=1.68, range 1.30-3.69) was left
unchanged -- it still comfortably contains the new median (1.591) and its
own claim (consistent with periodogram-estimator scatter) is unaffected.

**Sanity cross-check against other findings this session:** beta_2's new
median (2.48, well below true=3.00) and beta_3's new median (3.86, close
to true=4.00) are broadly consistent with the beta=3/4 SNR sweep findings
(`plots/beta3_4_snr_trend/`) -- at shift=7 (the same shift used here),
tau pins close to the prior's edge for both beta=3 (tau_mean=79.08) and
beta=4 (tau_mean=79.72), the known structural-ceiling regime. The
Fig. A.2 single-draw check (beta=3.82) also lands close to the new
beta_3 median (3.86).
